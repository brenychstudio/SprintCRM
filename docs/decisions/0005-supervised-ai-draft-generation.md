# ADR 0005: Supervised AI draft generation

**Status:** Proposed — technical production generation is operational; commercial quality is not yet accepted.

AI draft generation is an explicit, foreground user action in Campaign Full Workspace. The user must confirm the exact latest immutable research snapshot before the browser can request a draft. The browser sends only member, confirmed-snapshot, and idempotency IDs; the authenticated Edge Function derives permitted lead, campaign, proof, and research fields after organization authorization.

The Edge Function calls the OpenAI Responses API once with `store:false`, strict `draft_v1` JSON output, no tools, no web search, no arbitrary URL fetch, and an approximately 25-second timeout. Trusted instructions are separate from serialized untrusted CRM input. Raw prompts and provider responses are never persisted. A material instruction/quality change increments `prompt_version`; the schema version changes only if the JSON shape changes. Historical prompt versions remain auditable and immutable.

`outreach_draft_v2` is the commercial-quality contract over unchanged schema `draft_v1`. It defines the output as a first outreach rather than a proposal, targets 100–150 body words with a hard 180-word validation ceiling, limits research use to a few strongest observations, asks for one relevant value proposition and at most one verified proof reference, and requires one final low-pressure CTA. Subject guidance rejects clickbait, fake urgency, generic opportunity language, exaggerated benefits, and invented names. Sender signatures remain disallowed until verified sender identity becomes a reviewed product input.

Validation recognizes semantic low-pressure CTA structures in all four supported languages. Exactly one recognized CTA is preserved unchanged; only zero recognized CTA can invoke the single in-memory deterministic fallback, after which the full validator runs again; multiple or aggressive requests reject without repair. Spanish must use one explicit plural register, with Spain/vosotros preferred when public context clearly indicates Spain, while neutral `su` alone is not treated as formal evidence. If verified proof context describes a concept, reference, prototype, demo, speculative project, internal study, or case concept, a draft that names it must preserve that status and cannot imply unsupported client work. Substantive proof claims are never deterministically rewritten.

Completion atomically creates one immutable `outbound_messages` version (`source=ai`, `status=draft`) linked to its `ai_generations` ledger and research snapshot, writes audit events and the canonical `outreach_draft_saved` activity, and moves a member only to `draft_ready`. A changed latest research snapshot finalizes safely as `stale_research`, without a message or status change. Manual edits create later immutable manual versions.

This feature never sends email, creates a Gmail draft, approves/submits a message, changes a campaign to sent, schedules follow-ups, retries automatically, or runs in the background. It is gated by independent server `AI_RUNTIME_ENABLED` and `AI_DRAFT_GENERATION_ENABLED` switches and client `outreach_ops_enabled`, `ai_runtime_enabled`, and `ai_draft_generation_enabled` flags.

The first authenticated technical success used Research Version 2 and created immutable Message Version 1 with `gpt-5.4-mini` (1,011 tokens, 3,788 ms, HTTP 200). It stopped at `draft_ready` with no review, approval, Gmail draft, send, or campaign progression. Commercial review did not accept Version 1 because a semantic CTA false negative caused duplicate CTA completion, the Spanish register mixed vosotros and formal plural, concept/reference wording could imply a client relationship, and the first-touch body was too verbose. Version 1 remains immutable and must not be submitted for review.

`20260801000008_accept_ai_draft_prompt_v2.sql` is the forward-only start-contract change: `outreach_draft_v1` remains valid for historical compatibility, `outreach_draft_v2` is accepted for new jobs, both map to `draft_v1`, and unknown versions reject. It replaces no completion behavior and alters no historical row. After reviewed migration apply and Edge Function redeployment, acceptance requires exactly one supervised retest that appends Message Version 2 from Research Version 2 without altering Version 1.
