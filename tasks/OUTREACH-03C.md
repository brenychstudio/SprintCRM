## OUTREACH-03C-FIX-01 draft body validation diagnostics and targeted correction

- **Task goal:** Make rejected draft bodies precisely diagnosable through safe internal validation reasons, preserve the generic browser error, and correct only deterministic false positives in the plain-text and multilingual CTA/language checks.
- **Current-state evidence:** The first authenticated Hotel Marina Badalona draft reached OpenAI and the persistence lifecycle completed correctly. OpenAI/provider IDs, normalized usage, and duration were retained; the terminal failed ledger has `completed_at` and the safe detail `draft_validation:invalid_body`, with 956 total tokens consumed. It created no outbound message version or CRM activity; the member remains `research_ready`; no review, approval, Gmail, send, campaign progression, stale-job recovery, or cleanup occurred. The grouped `invalid_body` detail did not identify the failed predicate.
- **Files inspected and file plan:** `AGENTS.md`, the current branch/status, `supabase/functions/_shared/ai-draft.ts`, `ai-draft.test.ts`, `outreach-ai-runtime/index.ts`, this task record, and `docs/current-state.md`. Update only the shared parser, its unit tests, runtime rejected-result mapping, and these records; add no migration and do not alter generated types.
- **Implementation plan and safeguards:** Split body validation into stable safe reasons, retain `invalid_provider_response` with the generic browser message, and persist only `draft_validation:<reason>`. Keep unsupported-claim, placeholder, invented-recipient/sender, proof-context, human approval, no-send, and immutable-version protections intact. Provider bodies, prompts, CRM context, credentials, and raw provider responses remain neither persisted nor logged.
- **Narrow correction:** The prior CTA matcher accepted any question mark and its Spanish/Cyrillic markers were brittle. A Spanish body with a verified English company/case name containing `the` could therefore be classified as English when its accented Spanish CTA was not recognized. The parser now accepts normal multi-paragraph plain text and language-specific, low-pressure question structures in English, Spanish, Ukrainian, and Russian; it does not relax the CTA, language, format, claim, length, or pressure checks.
- **Risks, acceptance, and tests:** Main risks are weakening content safeguards or leaking generated content. Acceptance requires reason-specific failed validation, generic browser response, retained failed usage/provider IDs/duration with `output_payload=null`, and no message/activity/review/approval/Gmail/send/member mutation. Focused tests cover every body reason, valid multilingual CTAs, the Spanish false positive, strict `draft_v1`, and safe rejected-ledger fields. Required repository checks and `git diff --check` will be run before handoff.
- **Manual smoke, commit, and documentation:** No UI surface changed, so theme smoke is not applicable. Edge Function redeployment and one authenticated draft retest are pending; that retest must confirm the exact safe ledger detail and the same no-side-effect boundary.
